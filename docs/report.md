# MiniMax-H3 / FastH3 V2 NVFP4 研究结果

本轮结束状态：保留“先取得合格主片”的验收门，停止 GPU 测试。合格主片 0 条。最后一次释放核验为活跃实例 0、费率 0；这只是实验结束时的核验记录，不是面向读者的实时账户状态。

## 试验对象和样本范围

- 单张 Colab G4：NVIDIA RTX PRO 6000 Blackwell Server Edition，名义 96GB 显存。
- 模型：`FastVideo/FastVideo-FastH3-8-Step-V2-NVFP4-Consumer`。
- 固定模型 revision：`9d0d0d3ae69365aded83fab5562f00f9f06c12aa`。
- FastVideo 固定提交：`ce970eb715215c79a169658d7aa6c8a96e64891e`。
- 使用官方首帧接口 `InputConfig(pil_image=image, last_image=None)`，不是自动改成文生视频。
- 24fps；480 档 124 帧，768 档 243 帧。9 个时间网格点对应 8 次实际 DiT 前向。
- NVFP4、VSA sparsity 0.8、tile size 64、guidance scale 1、batch CFG 关闭；基线 VAE 编译关闭，模型常驻 GPU。

共有 7 条图生研发请求记录：P01–P03 因部署问题失败，P04 生成 480 档技术样片，M42/M43/M44 生成三条 768 档主片候选。公开资料不混入此前文生视频失败记录。

## 冷启动：一次可拆分的研发观察

| 阶段 | 秒 |
|---|---:|
| 实例到内核就绪 | 17.07 |
| 授权与 Drive 挂载 | 69.74 |
| 环境搬运、校验和解包 | 96.10 |
| 权重搬运与校验 | 315.38 |
| 模型框架初始化 | 19.93 |
| 首次请求及媒体检查 | 219.85 |
| 从观察到分配实例，到媒体校验完成 | **799.11** |

各阶段之间还有代码导入、补表搬运和调度间隙，所以不能直接把前六行相加当作总墙钟。排队内部状态未由服务端完整暴露；分配 API 等待和观察起点的不确定区间保存在会话成本表中。

按实例分配观察到首个请求开始划分，启动准备为 579.26 秒，约 1.617 CU；首个请求及校验为 219.85 秒，约 0.614 CU。合计约 2.231 CU，不能再加一次首片费用。首次文本编码阶段约 108.20 秒，含当次内核编译。

这不是三次正式冷启动统计。它使用提示词 v2 和当时的研究环境，不能作为稳定均值、P95 或不同卡型的比较。

## 内容验收

剧本《先吃饭，再思考》要求固定镜头、一个完整可见角色、左手饭碗、依次眨眼/挥手/看饭碗/最后摆尾，台词只有“先吃饭，再思考！”，没有字幕、其他人物或漫画特效。

- M42：语音自动转写与目标台词一致，但出现中文字幕、浮动文字和漫画符号。
- M43：字幕仍在，画面明显推近并裁切角色；自动转写检出额外发声。
- M44：抽样画面无字幕，角色完整，但开头已摆尾；台词自动转写未通过。不能仅凭 ASR 确定实际发音或主观音质。

三版提示词依次强化视觉约束和固定构图，最后一版以拼音表达同一句台词。所有首帧及尺寸派生图字节保持一致。种子、提示词同时发生过变化，不能把改善归因于某一个变量。

## 技术修复与证据限制

P01 修复受管环境 Ninja PATH；P02 补齐 I2V 参考时钟所需 AdaLN 表；P03 修复 FP4 原生内核与 Python API 的版本不一致。补表使用原始 BF16 投影的原生计算，不做插值或近似；完成 50 个 block、400 个 I2V 条目。

最终原始权重不覆盖，活动权重视图只去掉已由固定表替代的 100 个 AdaLN BF16 weight/bias 张量，保留张量数据逐字节一致。表与时间表绑定，不能任意换步数或时间点。

第一轮最终进程在计费监控 TLS 故障触发 VM 释放后，未回传最终退出码；残留退出记录属于较早停止的另一个进程。因此逐请求结果以媒体解码、哈希和请求记录为准。第二轮最后工作进程退出码为 0，官方 Drive 刷写和独立释放核验通过。退出码 0 本身也不是每条请求成功的证明。

公开资源采样为允许字段重导出：去掉绝对时间、账号、会话 ID 和 PID，保留相对秒、GPU 利用率/整卡显存/功率/温度，以及实际推理进程树的 CPU、RSS 和 I/O。RSS 求和可能重复共享页，1Hz 可能漏掉短生命周期子进程；I/O 是当时存活进程的累计计数，不是每条请求的精确增量。
